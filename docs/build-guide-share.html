Wi-Fi 탱크 "스낵 익스프레스" 제작 가이드

브라우저 대시보드로 조종하는 무선 탱크 차량 — 부품 구매부터 첫 주행까지. 전자공학 경험 없는 개발자가 실제로 만들며 밟은 지뢰를 전부 기록한 실전판입니다.

납땜 최소 (3곳) 브레드보드 조립 ESP32-C3 + TB6612 실측 검증 2026-10

01무엇이 만들어지나

완성하면 이런 것이 책상 위를 달립니다:

  • Wi-Fi 무선 탱크 — 집 공유기 또는 폰 핫스팟에 스스로 접속해 서버와 WebSocket으로 통신
  • 브라우저 조종 — 맥에서 띄운 대시보드(Next.js)에서 WASD 키로 전후진·제자리 회전
  • 데드맨 안전장치 — 키를 떼거나 Wi-Fi가 끊기면 300ms 안에 자동 정지. 폭주 원천 차단
  • 모터 비프음 — 버저 없이 모터 코일을 스피커로 사용: 부팅 삑 / 서버 접속 삑삑 / 연결 끊김 삐– / 배터리 부족(브라운아웃) 삐–삐–삐–
구조 한 줄 요약. 차량의 두뇌(ESP32-C3)는 판단하지 않습니다. 서버(맥)가 "왼쪽 모터 70% 전진" 같은 명령을 내리면 재생만 해요. 프론트엔드(대시보드) → API 서버(gateway) → 디바이스(차량)로 이어지는, 웹 개발자에게 익숙한 3계층 구조입니다.

03배선 — 올-브레드보드 방식

규칙은 단 두 개. ① 브레드보드의 같은 세로 5칸 줄 = 전기적으로 같은 노드. 예컨대 TB6612의 VM 핀이 꽂힌 줄에 배터리＋와 벅 컨버터 IN+를 같이 꽂으면 셋이 자동으로 이어집니다. ② 가장자리 레일은 빨강 = 3.3V 버스, 파랑 = GND 버스로 지정. 빨강 레일에 7.4V를 꽂는 순간 사고입니다 — 배터리＋는 레일을 거치지 않고 VM 줄로 직행.

TB6612와 ESP32-C3를 브레드보드 중앙 홈에 걸치게 꽂은 뒤, 아래 그림과 표대로 연결합니다.

TB6612 핀연결종류비고
VM배터리 ＋ (7.4V) + 벅 IN+ (같은 줄)전원모터용 파워. 상한 13.5V
GND파랑 레일 (배터리 −, 벅 IN−/OUT−, C3 GND 전부 여기로)기준두 전원계가 섞이는 유일한 지점 = 공통 0V 기준선
VCC · STBY · PWMA · PWMB빨강 레일 ← C3 3V3로직넷 다 3.3V에 묶기 = "칩 항상 깨움 + 출력 항상 허용". 속도는 AIN/BIN의 PWM으로만 제어

※ GPIO 3~6을 쓰는 이유: C3의 GPIO 2·8·9는 부팅 모드 결정 핀(strapping)이라 모터 드라이버를 물리면 부팅이 꼬일 수 있음.

납땜이 필요한 유일한 곳 (3곳)

  1. 벅 컨버터 패드 4개

    IN+/IN−에 배터리 쪽 전선, OUT+/OUT−에 브레드보드용 전선(또는 헤더핀만 납땜하고 듀폰으로). IN/OUT 방향 뒤집으면 C3까지 같이 죽습니다 — 실크 인쇄 재확인. 납땜 후 패드를 절연테이프로 덮기

  2. 모터 전선 끝 처리

    연선이라 브레드보드에 안 꽂히면 끝을 살짝 납땜해 굳히거나 듀폰 수컷 핀 압착. 납땜 후 가볍게 당겨 인장 테스트 — 주행 진동이 생각보다 셉니다

  3. 핀헤더 (해당 시)

    TB6612·C3에 헤더가 봉지에 따로 들어있는 타입이면 납땜. 미리 납땜된 버전을 사면 생략

벅 컨버터 첫 연결 순서 (C3 보호). 납땜 → C3는 아직 연결하지 않고 배터리 장착 → 멀티미터로 OUT+↔OUT−가 4.9~5.1V인지 확인 → 합격이면 배터리 빼고 OUT+를 C3 5V 줄에 연결. 멀티미터가 없으면 C3 대신 싼 부품(LED 등)으로 먼저 스모크 테스트.

04안전 수칙 — 전원 켜기 전 암기

  • USB와 벅 OUT+ 동시 연결 금지 — 두 5V 전원이 충돌. 플래시할 땐 OUT+를 브레드보드에서 뽑고 USB 연결 (배터리→VM은 동시여도 OK)
  • 18650 3개 직렬 금지 — 12.6V는 TB6612 상한(13.5V)에 너무 가까움
  • 배선 작업은 항상 배터리를 홀더에서 뺀 상태로. 전원 연결은 맨 마지막
  • 빨간 선(7.4V)이 VM·벅 IN+ 외엔 아무 데도 닿지 않는다 — 특히 C3의 어떤 핀에도
  • 첫 테스트는 차체를 뒤집어 바퀴를 공중에 — 데드맨 검증 전 바닥 주행 금지
  • 배터리(VM) 없이 모터 명령 금지 — VM 무전원 상태에서 TB6612에 PWM을 넣으면 칩이 C3의 3.3V에서 역급전으로 전류를 끌어 C3가 USB째 다운됨 (실측 재현). 모터 테스트 전 배터리부터

05실측으로 배운 함정 모음

스펙 문서엔 없고, 만들어보기 전엔 모르는 것들입니다. 이 섹션이 이 가이드의 존재 이유예요.

① ESP32-C3 슈퍼미니는 Wi-Fi가 그냥은 안 붙는다

안테나 매칭이 나쁜 개체가 많아, 기본 설정으론 공유기 스캔엔 잡히는데 접속이 안 됩니다. 증상: WPA 핸드셰이크가 reason 204 (HANDSHAKE_TIMEOUT)으로 반복 실패하고, 어렵게 붙어도 DHCP 요청이 유실돼 IP를 영영 못 받는 상태.

해법 두 줄. ① WiFi.setTxPower(WIFI_POWER_8_5dBm) — 송신 출력을 낮추면 오히려 붙습니다. begin() 직후에 호출 (이전에 부르면 무시되는 개체 있음). ② 고정 IP(WiFi.config(...))로 DHCP 단계를 통째로 우회. 둘 다 이 프로젝트 펌웨어에 이미 들어 있습니다. 접속 대기 중 수동 re-begin은 금지 — 붙으려는 연결을 끊는 자충수.

② PWM 주파수: 무소음(20kHz)을 포기해야 모터가 돈다

소형 기어모터는 코일 인덕턴스 때문에 고주파 PWM에서 저출력 토크가 바닥납니다. 같은 모터의 무부하 시작 임계(duty) 실측:

PWM 주파수움직이기 시작하는 duty판정
20 kHz0.9저속 제어 불능 — 회전 명령(0.6)에 무반응
1 kHz0.8부족
200 Hz0.5채택 — 구동 중 "드르륵" 가청음은 감수

여기에 데드밴드 보정을 얹습니다: 명령 0~1을 실듀티 0.55~1.0으로 선형 매핑 — 어떤 저속 명령도 "움직이는 최소 출력" 이상으로 변환돼 제자리 회전이 살아납니다. (펌웨어에 포함)

③ 플래시할 때마다 바퀴가 멋대로 돈다

플래시 중 C3의 GPIO가 전부 부유(floating) 상태가 되는데 PWMA/PWMB가 3.3V에 묶여 있어서, 노이즈가 그대로 모터 출력이 됩니다. AIN/BIN에 10kΩ 풀다운 저항이 근본 해결이고, 저항이 없는 동안의 수칙: 플래시 = 바퀴 공중.

④ 직진하는데 한쪽으로 휜다면 — 모터 탓이 아닐 수 있다

좌우 트랙 링크 개수부터 세어보세요. 한쪽이 1칸 많으면 헐렁해져 슬립으로 그쪽이 느려집니다 (실제 사례: 펌웨어 트림으로 17% 보정해도 안 잡히다가, 링크 1칸 제거로 트림 0 복귀). 그래도 남는 미세 드리프트는 모터 개체차 — 펌웨어의 TRIM_L/R 상수로 빠른 쪽을 몇 % 감쇠.

⑤ 자잘한 지뢰들

  • Wi-Fi는 2.4GHz만. 폰 핫스팟 쓸 땐 아이폰 "호환성 극대화" ON
  • 포트 확인은 ls /dev/cu.usbmodem* (tty 글롭은 놓칠 수 있음). USB 케이블은 반드시 데이터 지원 케이블
  • 모터 비프음은 공짜 기능: 고주파에선 구동 임계가 높아서(1kHz에서 duty 0.8) duty 29%로 소리만 내고 바퀴는 안 돕니다
  • 18650 충전 상태가 낮으면 두 모터 동시 기동 때 브라운아웃 리셋 — 펌웨어가 부팅 시 감지해 경고음(삐–×3)

06소프트웨어 — 펌웨어와 조종실

코드는 전부 공개 리포에 있습니다: github.com/jiyeonLeeLuda/ai-rc-bot — 차량 펌웨어는 firmware/vehicle/, 서버·대시보드는 apps/.

git clone https://github.com/jiyeonLeeLuda/ai-rc-bot.git
cd ai-rc-bot
  1. PlatformIO CLI 설치 
    python3 -m venv ~/.venvs/platformio
~/.venvs/platformio/bin/pip install platformio

    macOS 시스템 파이썬은 pip을 막아놔서(PEP 668) 전용 venv에 설치합니다.

  2. 펌웨어 설정 파일 만들기 
    cd firmware/vehicle
cp include/config.example.h include/config.h

    config.h에 본인 값 기입 — 1순위(집 Wi-Fi)와 2순위(폰 핫스팟)를 등록하면 부팅 시 스캔해서 보이는 쪽에 자동 접속합니다:

    #define WIFI_SSID     "your-wifi-ssid"      // 2.4GHz
#define WIFI_PASS     "your-wifi-password"
#define COCKPIT_HOST  "192.168.x.x"          // 본인 맥 IP: ipconfig getifaddr en0
#define WIFI2_SSID    "your-hotspot-ssid"    // 외부 주행용 (선택)
#define WIFI2_PASS    "your-hotspot-password"
#define COCKPIT2_HOST "172.20.10.x"          // 핫스팟에서의 맥 IP — 실측 확인

    고정 IP(기본 192.168.0.223)가 집 공유기 대역과 다르면 main.cpp의 WiFi.config 줄도 본인 대역에 맞게 수정.

  3. 플래시 (바퀴 공중! 벅 OUT+ 뽑고 USB 연결) 
    ~/.venvs/platformio/bin/pio run -e esp32-c3 -t upload \
  --upload-port /dev/cu.usbmodem*
  4. 조종실 서버 실행 (맥) 
    pnpm install
pnpm dev   # gateway :3001 + dashboard :3000

    음성/TTS 기능까지 쓰려면 gateway의 .env에 OPENAI_API_KEY 설정 (주행만 할 거면 불필요).

  5. 첫 주행 체크리스트

    ① C3 LED가 점멸(접속 중)→상시 점등(서버 연결) ② 비프음: 부팅 삑 → 접속 삑삑 ③ localhost:3000 대시보드에 차량 등장 ④ 바퀴 공중에서 WASD 네 방향 ⑤ 키 떼면 300ms 안에 정지(데드맨) 확인 ⑥ 통과하면 바닥에 내려놓고 첫 주행 🏁

막히면 여기부터. 시리얼 로그가 모든 걸 알려줍니다: ~/.venvs/platformio/bin/pio device monitor -b 115200. 부팅 로그에 주변 Wi-Fi 스캔 결과·접속 상태 코드·서버 주소가 전부 찍히게 돼 있어요. "스캔엔 보이는데 status=6 반복"이면 §05-①, 모터가 명령을 받는데(<- drive 로그) 안 돌면 배터리(VM 전원)부터 확인.

이 가이드는 2026-10 실제 제작 과정에서 검증된 내용만 담았습니다. 다음 확장(착좌 감지 → 주행모드 연출, 클락션 버튼, 저전압 컷오프)은 모노레포에서 진행 중 — 궁금하면 작성자에게 물어보세요. 🚚
